# 久留米・告示研修 日程更新LINE通知システム

Google Apps Script（GAS）とLINE Messaging APIを利用し、研修の日程ページを定期的に監視して、対象地域の情報に変更があった場合のみLINEグループへ自動通知するシステムです。

## 背景・課題

職場の複数名で告示研修への参加を予定していました。

研修の日程や募集情報は公式Webサイトで公開されていますが、定期的に人が確認する方法では、日程の追加や募集開始を見逃す可能性があります。

そこで、

**「Webサイトを人が見に行く」のではなく、「変更があったときだけ自動で知らせてもらう」**

仕組みを作成しました。

## システムの流れ

1. Google Apps Scriptを1時間ごとに自動実行
2. 公式の日程ページを取得
3. HTMLから「久留米」を含む情報を抽出
4. 前回取得した情報と比較
5. 変更がなければ通知しない
6. 変更を検知した場合のみLINEグループへ通知
7. 最新情報を次回比較用として保存

## 使用技術

- Google Apps Script（GAS）
- JavaScript
- LINE Messaging API
- UrlFetchApp
- PropertiesService
- GAS 時間主導型トリガー

## 工夫した点

### 1. 必要な変更だけを監視

Webページ全体を単純に監視すると、対象地域とは関係のない更新でも通知されてしまいます。

そこで、ページ内から「久留米」を含む情報だけを抽出し、その内容を比較する方式にしました。

### 2. 変更がない場合は通知しない

1時間ごとにWebサイトを確認しますが、毎回LINEを送信することはありません。

前回取得した情報と比較し、変更を検知した場合のみ通知します。

### 3. 初回実行時の誤通知を防止

初回実行時は、現在掲載されている情報を基準データとして保存し、LINE通知は行いません。

2回目以降、その基準から変更された場合に通知します。

### 4. 年度ではなく掲載情報そのものを監視

当初は、特定年度の情報が公開されたことを検知する方法を検討しました。

しかし、年度と実際の開催年が一致しない場合や、年度途中で新しい研修が追加される可能性があります。

そのため、特定年度の文字列ではなく、**「久留米に関する掲載情報そのもの」**の変化を監視する設計に変更しました。

### 5. 認証情報をソースコードから分離

LINE Messaging APIのアクセストークンや送信先IDはソースコードに直接記載せず、Google Apps ScriptのScript Propertiesで管理しています。

これにより、公開用コードに認証情報が含まれないようにしています。

## 実運用

テスト環境でLINE通知とWebサイト監視の動作を確認した後、実際に研修参加を予定しているメンバーのLINEグループで運用しています。

現在は1時間ごとに公式の日程ページを自動確認し、対象地域の掲載情報に変更があった場合のみ通知する仕組みになっています。

## 今後の改善

- WebサイトのHTML構造変更への対応
- 通信エラー・LINE送信エラー発生時の処理強化
- LINE通知に変更内容の詳細を表示
- 複数地域を選択して監視できる仕組みへの拡張
- 監視対象ページ変更時の異常検知

## セキュリティ

このリポジトリには、以下の情報を掲載しません。

- LINE Channel Access Token
- LINE Group ID
- その他の認証情報・個人情報

認証情報はGoogle Apps ScriptのScript Propertiesで管理しています。
