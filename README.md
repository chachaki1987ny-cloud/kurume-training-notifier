# 久留米・告示研修 掲載監視LINE通知システム

Google Apps Script（GAS）とLINE Messaging APIを利用し、日本臨床工学技士会の告示研修日程ページを定期的に確認して、対象となる久留米開催が掲載された場合にLINEグループへ自動通知するシステムです。

また、公式サイトを正常に取得できない場合や、日程表の構造を正常に読み取れなくなった場合には、監視システムの異常としてLINEへ通知します。


## 背景・課題

職場の複数名で告示研修への参加を予定しています。

久留米で開催予定の研修について、開催予定そのものは事前に把握できていましたが、公式サイトへの掲載や予約開始のタイミングを見逃す可能性がありました。

そこで、

**「Webサイトを人が定期的に確認する」のではなく、「対象の開催情報が掲載されたら自動で知らせてもらう」**

仕組みを作成しました。


## 現在の監視対象

現在は、以下の開催情報を監視しています。

- 開催日：2027年2月20日・21日
- 開催地：久留米
- 監視ページ：日本臨床工学技士会 告示研修日程ページ

予約画面はログインが必要なため、予約画面そのものの自動監視は行っていません。

その代わり、公式日程ページに対象の久留米開催が掲載されたことを検知した時点でLINE通知を送り、通知を受けたメンバーが予約画面を確認する運用としています。


## システムの流れ

1. GASの時間主導型トリガーで1時間ごとに自動実行
2. 公式の告示研修日程ページへアクセス
3. HTTPステータスを確認
4. HTMLから日程表を取得
5. 日程表を正常に読み取れているか確認
6. 「久留米」と「2月20日または2月21日」を含む開催情報を検索
7. 対象情報がなければ何もせず終了
8. 対象情報を初めて検知した場合のみLINEグループへ通知
9. 通知成功後は通知済み状態を保存し、同じ情報を繰り返し通知しない


## 使用技術

- Google Apps Script
- JavaScript
- LINE Messaging API
- Script Properties
- GAS 時間主導型トリガー
- HTTP通信（UrlFetchApp）
- HTML解析


## 工夫した点

### 1. 必要な開催情報だけを監視

初期バージョンでは、「久留米」を含む掲載情報全体の変化を監視していました。

しかし実運用では、既存の久留米関連情報が変更されただけでも通知されることが分かりました。

そこで監視条件を見直し、

**「久留米」＋「2月20日または2月21日」**

という具体的な条件に変更しました。

これにより、対象外の久留米情報の変更による不要な通知を減らしています。


### 2. 同じ情報を繰り返し通知しない

対象情報を検知してLINE通知に成功すると、Script Propertiesに通知済み状態を保存します。

そのため、1時間ごとに監視を続けても、同じ開催情報について繰り返し通知されません。


### 3. LINE送信失敗時の再試行

LINE APIへの送信結果をHTTPステータスコードで確認しています。

送信に成功した場合のみ通知済み状態を保存します。

送信に失敗した場合は通知済みにせず、次回の定期実行時に再度通知を試みます。


### 4. 監視システム自体の異常を検知

対象情報だけでなく、監視処理そのものが正常に動作しているかも確認しています。

以下のような場合には監視異常としてLINE通知します。

- 公式サイトへのアクセスに失敗した場合
- HTTPステータスが200以外の場合
- HTMLの日程表を正常に取得できない場合
- 「開催日」「開催地」「会場」など、日程表として必要な構造を確認できない場合

これにより、サイト側の構造変更などによって監視処理が正常に機能しなくなった場合にも気づけるようにしています。


### 5. 異常通知の連続送信を防止

監視異常を検知すると、Script Propertiesに異常通知済み状態を保存します。

同じ異常状態が続いても、1時間ごとにLINE通知を繰り返すことはありません。

監視状態が正常に戻った場合には異常状態を解除し、その後あらためて異常が発生した場合には再び通知できるようにしています。


### 6. 認証情報をコードに書かない

以下の情報はソースコードに直接記載せず、GASのScript Propertiesで管理しています。

- `LINE_GROUP_ID`
- `LINE_CHANNEL_ACCESS_TOKEN`

そのため、GitHub上のコードには実際のグループIDやアクセストークンは含まれていません。


## 実運用での改善

初期バージョンでは、久留米に関連する表の行全体を保存し、前回取得時との違いを比較していました。

実際に運用したところ、久留米関連の掲載内容に変化が発生し、LINE通知が送信されました。

しかし、この方式では、

**「目的としている開催情報の掲載」**

と

**「その他の久留米関連情報の変更」**

を区別できませんでした。

そこで、実運用で得られた結果をもとに監視ロジックを変更し、現在は対象となる開催日と開催地を明示的に判定しています。

さらに、

**「監視プログラムが動いていても、公式サイトの構造変更によって必要な情報を読み取れなくなる可能性がある」**

ことを考慮し、監視システム自体の異常検知も追加しました。


## 動作確認

実装後、以下の動作を確認しています。

- 通常時はLINE通知を送信しない
- 対象情報が存在しない場合は正常終了する
- 意図的に日程表の構造判定を失敗させると、監視異常のLINE通知が送信される
- 正常な状態へ戻した後は、再び通常の監視処理へ復帰する


## 今後の改善案

- 日付表記の変化に対する判定方法の強化
- HTML構造変更に対する解析方法の強化
- 監視対象となる開催情報を設定値として管理
- 複数地域・複数開催日の監視への対応
- エラーログの保存・確認方法の改善
